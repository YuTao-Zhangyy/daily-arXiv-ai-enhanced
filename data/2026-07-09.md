### [1] [Seekable OCI: Lazy-Loading Container Images via Range-Request Indexing](https://arxiv.org/abs/2607.06868)
*James Thompson,Wayne Mesard,Jesse Butler,Sri Saran Balaji Rajakumar,Henry Wang*

TL;DR: SOCI 是一种兼容标准 OCI 镜像和仓库的容器镜像懒加载方案，通过外部索引、FUSE 和 HTTP Range Requests 按需读取镜像内容，大幅缩短大镜像冷启动时间；当启动访问内容较少时效果显著，但访问密度很高时完整并行拉取更优。


<details>
  <summary>Details</summary>
Motivation: 容器镜像拉取是 Kubernetes Pod 启动时间的主要来源。传统方式必须先完整下载镜像，即使应用启动时只访问其中一小部分内容，导致大镜像冷启动延迟高、资源浪费明显。因此需要一种无需改动现有镜像格式和部署生态的懒加载方案。

Method: 构建 Seekable OCI 架构：为标准 OCI 镜像生成外部索引，将文件映射到压缩层中的字节范围；运行时通过 FUSE 文件系统拦截文件访问，并使用 HTTP Range Requests 按需读取所需数据；索引以 OCI referrer artifact 形式存储，保持镜像与仓库兼容。

Result: 在 1.3 GB Python Web 服务镜像上，SOCI 将冷启动拉取时间从 20 秒降至约 2.8 秒，获得 7.4 倍加速；在 2.5 GB 镜像上加速达 9.3 倍。实验显示访问密度低于 80% 时懒加载更优，高于该阈值时并行完整拉取更快。SOCI 已在 Amazon EKS 与 ECS Fargate 生产环境部署，并自 2023 年起服务懒加载请求。

Conclusion: SOCI 证明了在不修改 OCI 镜像、镜像仓库或部署工具链的前提下，通过外部索引与按需加载机制可显著降低 Kubernetes/容器环境中的冷启动拉取时间，尤其适用于启动阶段只访问少量镜像内容的大镜像场景。

Abstract: Container image pulling accounts for the majority of pod startup time in Kubernetes environments. Standard pull downloads the entire image before the container can start, even when the application accesses only a fraction of the image content at startup. SOCI builds an external index over standard OCI images, mapping files to byte ranges within compressed layers. At runtime, a FUSE filesystem intercepts file accesses and serves them via HTTP range requests. Unlike prior approaches that require image format conversion, SOCI works with unmodified images and standard registries. The index is stored as an OCI referrer artifact, requiring no changes to images, registries, or deployment tooling. On a 1.3 GB Python web service image, SOCI reduces cold-start pull time from 20 seconds to approximately 2.8 seconds (7.4x speedup), with pull time independent of image size. Larger images see larger speedups (9.3x on a 2.5 GB image) because SOCI pull time is constant while standard pull scales linearly. We measure a crossover at 80% access density: below this, lazy loading wins; above, parallel full pull is faster. SOCI lazy loading is deployed in production on Amazon EKS and Amazon ECS Fargate (which launched 18.4 million tasks per day during Prime Day 2025), and has been serving lazy-load requests since 2023. EKS Auto Mode uses SOCI's parallel pull mode for GPU instances.

Motivation: IAB 网络通过复用接入与回传频谱降低毫米波接入网络部署成本，但无线回传段容易成为性能瓶颈，且毫米波回传依赖视距条件。引入 Sub6 回传链路可提升容量与鲁棒性，因此需要高效的流量工程与转发策略来充分利用异构回传资源。

Method: 提出 PHaul 转发引擎：将离线路径选择启发式算法与基于近端策略优化（PPO）的在线深度强化学习代理结合；利用 IAB 无线回传网络数字孪生周期性采样输入流量，并更新流到路径的映射关系。

Result: 在真实规模回传拓扑中，PHaul 的执行时间低于 10 秒；相比两种替代启发式方法，在多种网络配置下吞吐效率最高提升 36%，公平性最高提升 20%；并且对训练和推理阶段拓扑不一致具有鲁棒性。

Conclusion: PHaul 能有效提升 Sub6 增强型 IAB 网络中无线回传的转发性能与鲁棒性，在不同网络配置及链路失效导致的拓扑差异下仍保持较好泛化能力。

Abstract: 3GPP Integrated Access and Backhaul (IAB) allows operators to deploy outdoor mm-wave access networks in a cost-efficient manner, by reusing the same spectrum in access and backhaul. In IAB networks the performance bottleneck is the wireless backhaul segment, where efficient forwarding strategies are needed to effectively use the available capacity. In addition, the performance of the mm-wave IAB backhaul segment is contingent on the availability of line of sight (LoS) conditions in the selected deployment sites. To mitigate LoS dependence, in this paper, we propose to complement the mm-wave backhaul segment of IAB networks with additional Sub6 backhaul links, which contribute to the capacity and robustness of the backhaul network. We refer to IAB networks combining Sub6 and mm-wave links in the backhaul as Sub6 enhanced IAB networks. In this context, the main contribution of this paper is PHaul, a forwarding engine for Sub6 enhanced IAB networks that accomodates different traffic engineering criteria, and combines an offline path selection heuristic with an online Deep Reinforcement Learning (DRL) agent based on Proximal Policy Optimization (PPO). By leveraging a network digital twin of the IAB wireless backhaul, PHaul periodically samples the input traffic of the backhaul network and updates flow to path mappings, with execution times below 10 seconds in realistic backhaul topologies. We present an exhaustive performance evaluation, where we demonstrate that PHaul can achieve gains of up to 36\% in throughput efficiency and of up to 20\% in fairness, when compared against two alternative heuristics in a wide range of network configurations. We also demonstrate that PHaul is robust to differences between the network topologies considered in the training and inference phases, which can occur in practice due to link failures.
